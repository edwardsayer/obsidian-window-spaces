# Window Spaces 插件改進項目

## 🚨 待修正的重大問題

### 1. 視窗狀態儲存範圍問題

**問題描述**: 目前採用儲存整個 Workspace 的作法，會影響到主視窗狀態

- **現象**: 儲存的 JSON 中 `layouts.workspace.layout` 包含 `main`, `left`, `right`, `left-ribbon` 等物件
- **影響**: restore 時會修改主視窗的佈局狀態
- **原因**: 參考 workspaces-plus 外掛的作法，但未考慮到只應儲存活動視窗的需求
- **修正方向**: 只儲存當前活動視窗的相關狀態，排除主視窗佈局

### 2. Floating 視窗資料污染問題

**問題描述**: floating 陣列會儲存所有視窗配置，應只儲存當前活動視窗

- **現象**: 每次儲存時會影響到其他已存在的視窗配置資料
- **影響**: 可能導致其他視窗的配置被意外覆蓋或修改
- **修正方向**: 在 floating 陣列中只處理當前活動視窗的配置項目

### 3. Quick Command 選單污染問題

**問題描述**: 動態生成的恢復命令會污染 Quick Command 選單

- **現象**: Quick Command 中出現 `Restore window layout: Window1` 等動態選單項目
- **影響**: 造成選單冗長，用戶體驗下降
- **修正方向**: 只保留兩個核心命令
  - `Save active window layout`
  - `Restore window layout` (彈出選擇對話框)

## 🔧 修正策略

### 視窗狀態精確提取

```typescript
// 目標：只提取活動視窗相關的狀態
interface WindowState {
  windowId: string;
  workspace: {
    // 只包含活動視窗的佈局資訊
    // 排除 main, left, right 等主視窗佈局
  };
  floating: {
    // 只包含當前活動視窗的配置
  };
}
```

### 資料隔離機制

- 實現視窗狀態的精確識別
- 建立活動視窗與其他視窗的資料隔離
- 確保 restore 操作只影響目標視窗

### 命令清理

- 移除動態命令註冊機制
- 簡化命令面板選單
- 保持核心功能的易用性
